# FOSSEE Task 2 — Submission Requirements and Plan

Confirmed from the official pages (fetched 13 Aug 2026).

---

## The workflow

1. Create an account on **esim.fossee.in**
2. Submit a **proposal** via the proposal form
3. **Wait up to 7 working days** for approval by email ← start this now
4. After approval, build the eSim project and simulate
5. Upload project files + abstract **through the web interface only — not email**
6. Post the internship forms
7. Separately email `contact-esim@fossee.in`, subject exactly:
   `eSim Semester Long Internship - Autumn 2026 Submission Task 2`

## Required project files — a ZIP of the eSim project folder

**Do not rename the project folder.** It must contain:

| File | What it is | Have it? |
|---|---|---|
| `analysis` | eSim analysis settings | ✗ |
| `.bak` | schematic backup | ✗ |
| `.cir` | netlist generated by eSim | ✗ |
| `.cir.out` | netlist after Ki→Ng conversion | ✗ |
| `.pro` | KiCad project file | ✗ |
| `.sch` | **schematic** | ✗ |
| `.sub` | subcircuits, if used | n/a |
| `cache.bak` | symbol cache | ✗ |
| `.lib.xml` | library XML | ✗ |
| **VHDL files** | **required for NGHDL projects** | ✓ |

**This confirms a real eSim project with a schematic is mandatory.** Our
command-line ngspice netlists do not satisfy it on their own.

## Required abstract — PDF, mandatory sections

Template: https://static.fossee.in/esim/template/CSP_Template.docx

1. Title
2. Theory / description
3. **Circuit diagram(s)**
4. **Results / Output (ngspice and Python plots)**
5. References

Note it wants *ngspice and Python plots* — so waveform screenshots from the
simulation, and ideally a Python-plotted figure from the raw data.

It is plagiarism-checked, so the text must be original. Ours is.

## Plan

### Now — start the 7-day clock
Submit the proposal (text in `docs/proposal.md`).

### Then — build the eSim project
1. Create project `CAN_Bus_MixedSignal` in eSim
2. Place the `can_node_top` NGHDL symbol (already generated) ×2 or ×4
3. Draw the analog PHY: driver switches, 120 Ω terminations, bias network,
   bus capacitance, differential receiver
4. Add sources: 2 MHz clock, reset, transmit requests, `id_sel` constants
5. Add ADC/DAC bridges at every analog–digital boundary
6. Annotate, assign footprints if required, run ERC
7. KiCad → Ngspice conversion
8. Simulate from the eSim GUI
9. Capture waveforms

### Finally — the abstract
Write to the CSP template with theory, circuit diagrams, ngspice and Python
plots, and references. Export to PDF.

---

## Risk

The schematic is the only real unknown left. The netlists work, so the
electrical design is proven — but drawing it in eSchema, getting the NGHDL symbol
placed correctly, and having Ki→Ng produce a working netlist is a distinct piece
of work with its own failure modes (the Day 11 `UnboundLocalError` came from
exactly this path, and is already patched).

Starting with a **two-node** schematic rather than four is the sensible order:
prove the flow works, then scale.
